# Собственный Docker-образ на базе Debian для FreeUnit с PHP

[English](README.md) · [Русский](README.ru.md) — историю релизов смотрите в
[CHANGELOG.ru.md](CHANGELOG.ru.md).

Репозиторий собирает Docker-образы, объединяющие демон [FreeUnit][upstream]
(форк NGINX Unit) со встроенным модулем PHP, установленным из готовых
Debian-пакетов.

- **Апстрим FreeUnit:** <https://github.com/freeunitorg/freeunit>
- **Сборки пакетов для trixie:** <https://github.com/6RUN0/freeunit/releases> —
  форк, который организует `.deb`-сборки под Debian trixie, устанавливаемые этим
  образом.
- Дистрибутив: Debian **trixie** (только amd64 — апстрим публикует `.deb`
  лишь под amd64).
- Версии PHP: 8.3, 8.4, 8.5 (по одному встроенному PHP на образ — встраиваемый
  SAPI допускает только один).

Единый параметризованный `Dockerfile` покрывает всю матрицу через build-args;
`Makefile` собирает каждый вариант.

[upstream]: https://github.com/freeunitorg/freeunit

## Получение образа

Готовые образы публикуются в GitHub Container Registry по адресу
`ghcr.io/6run0/freeunit-php`. Каждый релиз публикует по одному образу на каждую
ветку PHP (8.3 / 8.4 / 8.5) под несколькими тегами, чтобы можно было закрепиться
настолько свободно или строго, насколько нужно:

| Шаблон тега | Пример | Указывает на |
|-------------|--------|--------------|
| `latest` | `ghcr.io/6run0/freeunit-php` | свежий выпуск, PHP по умолчанию (8.4) |
| `<версия>` | `:0.4.0` | этот выпуск репозитория, PHP по умолчанию |
| `<suite>-php<X.Y>` | `:trixie-php8.3` | свежий выпуск на ветке PHP (двигается вперёд) |
| `<версия>-php<X.Y>` | `:0.4.0-php8.3` | выпуск репозитория на ветке PHP |
| `<suite>-<выпуск-freeunit>-php<X.Y>-v<версия>` | `:trixie-1.37.2-2-php8.3-v0.4.0` | сборка FreeUnit в выпуске репозитория на ветке PHP |

```bash
docker pull ghcr.io/6run0/freeunit-php:trixie-php8.4
```

Теги `latest` и `<suite>-php<X.Y>` плавающие - следующий выпуск перенаправляет
их; с 0.4.0 они указывают на образ без root (см. [Запуск без root](#запуск-без-root)).
Теги `<версия>...` остаются привязанными к одному выпуску: workflow выпуска
отказывается перезаписать существующий. До 0.3.0 тег сборки FreeUnit был без
версии (`trixie-1.37.2-2-php8.3` - образ 0.3.0 с root). Для байт-стабильного
деплоя закрепляйтесь по дайджесту (`...@sha256:...`) - именно эту форму
проверяет и `gh attestation verify` (см. раздел "Примечания").

## Сборка

```bash
# Образ по умолчанию (trixie, php8.4)
docker build -t freeunit-php .

# Конкретная версия PHP
docker build --build-arg PHP_VER=8.3 -t freeunit-php:8.3 .

# Зафиксировать другой релиз FreeUnit
docker build \
  --build-arg FREEUNIT_VERSION=1.35.5-1 \
  --build-arg FREEUNIT_RELEASE=1.35.5-build4 \
  -t freeunit-php .
```

Или через Makefile:

```bash
make            # собрать все версии PHP (8.3, 8.4, 8.5)
make php8.3     # собрать один вариант
make latest     # собрать PHP по умолчанию (8.4) и пометить тегом :latest
make test       # собрать PHP по умолчанию и прогнать интеграционный smoke-тест
make lint       # запустить все установленные линтеры (hadolint, shellcheck, rumdl, typos)
make scan       # CVE-сканирование образа по умолчанию (trivy/grype, если установлены)
```

Значения по умолчанию для конкретного релиза (`SUITE`, `PHP_VER`,
`FREEUNIT_VERSION`, `FREEUNIT_RELEASE`) хранятся в ARG-ах `Dockerfile`, а
`Makefile` читает их оттуда, поэтому смена версии — это одна правка в
`Dockerfile`. Любую переменную можно переопределить в командной строке,
например `make FREEUNIT_RELEASE=1.35.6-build1 FREEUNIT_VERSION=1.35.6-1`.

## Запуск

```bash
docker run -d --name app \
  -p 8080:8080 \
  -v "$PWD/www:/www:ro" \
  -v "$PWD/config.json:/docker-entrypoint.d/config.json:ro" \
  freeunit-php
```

Когда каталог состояния `/run/freeunit` пуст (новый контейнер или каждый запуск
с tmpfs на `/run`), entrypoint поднимает демон на управляющем сокете, применяет
всё содержимое `/docker-entrypoint.d/`, а затем перезапускает демон на переднем
плане. Если эта первоначальная настройка не удалась, каталог состояния
очищается, чтобы следующий запуск начался с чистого листа.

Запускаемые примеры лежат в [`examples/`](examples/), по одному на подкаталог:

- [`examples/basic/`](examples/basic/) — самодостаточный, ужесточённый по
  безопасности деплой (маленький `Dockerfile` запекает приложение и его конфиг в
  образ): `cd examples/basic && docker compose up --build`.
- [`examples/cron-hook/`](examples/cron-hook/) — система хуков entrypoint: один
  образ работает в двух ролях, веб-сервер Unit и долгоживущий cron-раннер
  `supercronic`, выбираемых для каждого контейнера командой, без второго образа и
  без переопределения entrypoint.

### Соглашения `/docker-entrypoint.d/`

Файлы применяются в лексическом порядке, по расширению:

| Расширение | Действие |
|------------|----------|
| `*.sh`     | Исполняется от пользователя контейнера. |
| `*.pem`    | Загружается как набор сертификатов с именем файла (без `.pem`). |
| `*.json`   | Отправляется `PUT`-запросом в `config` Unit через управляющий сокет. |

Файлы прочих типов логируются и игнорируются.

Скрипт, который собирает конфигурацию при старте, пишет её в
`$ENTRYPOINT_GENERATED_DIR` (`/run/docker-entrypoint.d`), а не в образ, доступный
только для чтения: после `*.pem` и `*.json` из `/docker-entrypoint.d`
применяются файлы этого каталога (сертификаты обоих каталогов - раньше любой
конфигурации, сгенерированная конфигурация - последней). `*.sh` оттуда не
исполняются.

> Несколько `*.json` **не** объединяются: `PUT /config` заменяет всю
> конфигурацию, поэтому в силу вступает только последний файл (entrypoint
> предупреждает, если в каталоге их больше одного). Поставляйте один
> объединённый файл конфигурации.

Явная команда `freeunitd ...` / `freeunitd-debug ...` получает недостающие флаги
`--no-daemon`, `--control`, `--pid`, `--statedir` и `--tmpdir`; один из четырёх
последних с другим значением останавливает запуск с ошибкой, потому что
первоначальная настройка пишет по путям entrypoint. `freeunitd --version` /
`--help` / `-h` выполняются как есть, без первоначальной настройки.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `UNIT_ENTRYPOINT_QUIET_LOGS` | _не задана_ | Если задана, отключает логи entrypoint. |
| `HOME` | `/home/nonroot` | Может быть только для чтения (ssh, composer и drush работают); если приложение пишет туда - смонтируйте. |

Переменных `APPLICATION_USER/UID/GROUP/GID/DIR/CHOWN` из 0.3.x больше нет: образ
не создаёт пользователя при старте и не меняет владельцев.

### Запуск без root

Образ стартует от `nonroot` (uid:gid `65532:65532`, домашний каталог
`/home/nonroot`): `tini`, entrypoint, мастер Unit и воркеры PHP работают от этого
пользователя, контейнеру не нужно ни одной capability. Производный `Dockerfile`,
который ставит пакеты, переключается на `USER 0:0` перед `RUN apt-get` и
возвращает `USER 65532:65532` в конце.

Ужесточённый запуск - корневая ФС только для чтения, без capabilities, каждый
путь для записи - точка монтирования во владении процесса. Каталог хоста для
`/tmp` должен принадлежать uid контейнера (`sudo install -d -m 0700 -o 65532 -g
65532 tmp`); отсутствующий Docker создаст от root, и запуск остановится с
подсказкой про `/tmp`.

```bash
docker run -d --name app -p 8080:8080 \
  --read-only --cap-drop=ALL --security-opt=no-new-privileges \
  --tmpfs /run:size=16m,uid=65532,gid=65532,mode=0700 \
  -v "$PWD/tmp:/tmp" \
  -v "$PWD/www:/www:ro" \
  -v "$PWD/config.json:/docker-entrypoint.d/config.json:ro" \
  freeunit-php
```

| Путь | Что хранит | Объём | Монтирование |
|------|------------|-------|--------------|
| `/run` | управляющий сокет, pid, каталог состояния `/run/freeunit`, `/run/docker-entrypoint.d` | КиБ | tmpfs |
| `/tmp` | буферы тел запросов Unit (`--tmpdir /tmp`), загрузки и временные файлы PHP, сессии | до `max_body_size` на запрос | bind mount на диск (рекомендуется) или tmpfs с `size` |

- **Подходит любой не-root uid:gid** (`--user 1000:1000`): tmpfs получают те же
  `uid=`/`gid=`, bind mount должны быть доступны ему на запись. Entrypoint
  раньше всего остального проверяет запись в `/var/run`, каталог состояния и
  `/tmp` и останавливается с подсказкой, какой точки монтирования не хватает. У
  uid без записи в passwd `HOME=/`, и ssh для него не запускается: сайт, которому
  нужен ssh, добавляет запись в своём образе.
- **`HOME` может остаться только для чтения** (`/home/nonroot`, пустой, 0755):
  ssh, composer и drush работают без записи туда. Приложение, которое пишет в
  `HOME` (`known_hosts`, кеш), монтирует туда tmpfs или каталог во владении uid.
- **`/tmp` должен быть доступен на запись uid процесса**: туда идут объёмные
  временные файлы (тела запросов, загрузки PHP). Под `read_only` смонтируйте
  туда каталог хоста во владении этого uid (рекомендуется) или tmpfs с `size`.
  `php.ini` образа (`cli` и `embed`) направляет `session.save_path` в `/tmp`;
  остальные временные пути PHP остаются на умолчании `/tmp`.
- **Воркеры Unit не наследуют окружение контейнера:** задайте `HOME` в блоке
  `environment` приложения, если PHP отправляет почту или запускает ssh.
- **Не задавайте `user`/`group` в конфигурации Unit:** Unit без root запускает
  воркеры от своего пользователя.
- **Порты ниже 1024** требуют `net.ipv4.ip_unprivileged_port_start=0` (умолчание
  Docker с Engine 20.10; если не уверены, задайте явно через `--sysctl` /
  `sysctls:`).
- **Запуск от root** (`--user 0:0`, `user: root`): до любой записи entrypoint
  отдаёт stdio пользователю 65532 и перезапускает себя от `65532:65532` без
  дополнительных групп и с `no_new_privs`, записав предупреждение в лог. Для
  этого нужны capabilities по умолчанию или как минимум `CAP_SETUID`,
  `CAP_SETGID`, `CAP_CHOWN` и `CAP_KILL` (tini передаёт `docker stop` процессам
  65532); без них запуск останавливается с ошибкой. `tini` (PID 1) в этом
  режиме остаётся root с capabilities контейнера - это запасной путь, а не
  рекомендуемая настройка. Проверка работоспособности, которую Docker тогда
  запускает от root, обращается к сокету от его владельца.
  Не-root uid с группой 0 среди групп отвергается.
- **Управляющий API доступен коду приложения.** Управляющий сокет (0600),
  каталог состояния и каталог сгенерированных файлов принадлежат тому же uid,
  что и воркеры PHP: выполнение кода в PHP перенастраивает Unit (маршруты,
  слушатели, `share`, `environment`) до перезапуска контейнера. Unix-сокет
  закрывает SSRF, но не RCE; это цена Unit без root.
- `docker exec` выполняется от пользователя контейнера. `docker exec -u 0`
  обходит защитное условие: такой root создаёт файлы во владении root, которые
  процесс потом не перепишет.

### Хуки entrypoint

Производный образ добавляет режим запуска одним файлом в
`/docker-entrypoint-hook.d/` (см. [`examples/cron-hook/`](examples/cron-hook/)).
Entrypoint написан на POSIX sh (`/bin/sh`, в образе - dash) и подключает (`.`)
каждый `*.sh` оттуда, поэтому хук - тоже POSIX sh; хук на bash падает при
старте. Файл хука:

- только определяет функции `handle_<cmd>` (`<cmd>` из `[A-Za-z0-9_]`), без кода
  верхнего уровня; принадлежит root и не доступен на запись группе/всем;
- выбирается, когда `command -v handle_<cmd>` печатает это имя (функция
  оболочки; исполняемый файл с таким именем в `PATH` не считается), и
  вызывается как `handle_<cmd> "$@"` с полным argv; обязан сделать `exec`
  итогового процесса, `set -e` внутри него не действует;
- начинает имя каждой своей переменной с префикса `<cmd>_`: в POSIX sh нет
  `local`, а `UNIT_*`, `ENTRYPOINT_*`, `_ep_*` принадлежат entrypoint.

### Модель безопасности

Относитесь к `/docker-entrypoint.d/*.sh` и `/docker-entrypoint-hook.d/*.sh` как к
доверенному вводу: они исполняются от пользователя контейнера с доступом к
управляющему API. Entrypoint отвергает файл хука, который не принадлежит root
или доступен на запись группе/всем, поэтому взломанное приложение не подложит
код в следующий запуск.

## Примечания

- **Только amd64.** FreeUnit публикует `.deb` под amd64; сборки `linux/arm64`
  нет.
- **Плавающая основа.** Образ фиксирует релиз FreeUnit, но база Debian и пакеты
  PHP с deb.sury.org — rolling, а на этапе сборки выполняется `apt
  full-upgrade`, поэтому две сборки одного тега не бит-в-бит воспроизводимы.
- Проверка целостности `.deb` — это сверка SHA256 с собственным `SHA256SUMS`
  релиза, который сам закреплён в репозитории по своему дайджесту, поэтому
  подменённый релиз не сможет подсунуть подходящий файл контрольных сумм
  (целостность, не апстрим-подлинность — подписи FreeUnit нет).
- **Публикуемые образы несут аттестации.** Каждый образ, отправленный в GHCR
  релизным воркфлоу, записывает безключевую аттестацию происхождения сборки и
  SBOM в формате SPDX как аттестации Sigstore. Проверьте скачанный образ, прежде
  чем доверять ему:

  ```bash
  gh attestation verify \
    oci://ghcr.io/6run0/freeunit-php@<digest> --owner 6RUN0
  ```
