# Список изменений

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

Версии здесь относятся к **упаковке** (этому репозиторию), а не к встроенному
ПО; каждый релиз фиксирует версии FreeUnit и PHP, которые он поставляет.

## [Не выпущено]

### Добавлено

- Аттестации цепочки поставки при релизе: `release.yml` теперь генерирует
  SPDX-SBOM для каждого публикуемого образа и записывает безключевые (OIDC)
  аттестации происхождения сборки и SBOM, которые публикуются в GHCR как
  OCI-referrer'ы манифеста образа. Проверить скачанный образ:
  `gh attestation verify oci://ghcr.io/6run0/freeunit-php@<digest> --owner 6RUN0`.
- `.github/workflows/check-upstream.yml`: еженедельная (и запускаемая вручную)
  задача, которая следит за репозиторием пакетов FreeUnit и при новом релизе
  открывает PR с бампом — она пересчитывает закреплённый якорь доверия
  `FREEUNIT_SHA256SUMS_SHA256` и отказывается обновляться, если в новом
  `SHA256SUMS` нет модульного `.deb` для каждой ветки PHP из матрицы.
- `.github/dependabot.yml`: еженедельные сгруппированные PR с бампами для
  GitHub Actions, закреплённых по SHA.
- В lint-задачу CI добавлены проверки воркфлоу и markdown: actionlint, zizmor
  (аудит безопасности воркфлоу) и rumdl.
- Trivy-скан в CI теперь выдаёт SARIF и загружает его в GitHub code scanning,
  поэтому CVE отображаются во вкладке Security и отслеживаются во времени.
- `.github/workflows/security-scan.yml`: еженедельный (и запускаемый вручную)
  повторный trivy-скан *опубликованных* образов в GHCR по каждой ветке PHP,
  чтобы уязвимости, раскрытые после релиза, всплывали без нового push.
- `examples/`: самодостаточный, ужесточённый по безопасности деплой — маленький
  `Dockerfile` запекает приложение и его конфиг Unit в опубликованный базовый
  образ (конфиг копируется в `/docker-entrypoint.d`, без bind-mount'ов),
  запускается с cap-drop + `no-new-privileges` и воркером со сбросом до
  пользователя `unit`.

### Изменено

- Матрица сборки+smoke в CI теперь идёт через Buildx с послойным кэшем GitHub
  Actions на каждую версию PHP (`type=gha`), поэтому повторные прогоны
  переиспользуют слои apt/загрузок вместо сборки с нуля; trivy-скан переиспользует
  образ 8.4, а не собирает свой.

### Исправлено

- Контейнер не стартовал под описанным в README hardening (`--cap-drop=ALL …`):
  каталог `/var/lib/unit` принадлежал `unit:unit`, поэтому root-мастер `unitd` —
  лишённый `CAP_DAC_OVERRIDE` из-за сброшенных capabilities — не мог создать свои
  хранилища `certs/` и `scripts/` (`mkdir … EACCES`) и падал на сохранении
  конфигурации. Теперь каталог состояния остаётся во владении root (мастер по
  замыслу работает от root), поэтому запуск с cap-drop работает; воркер
  приложения по-прежнему сбрасывается до `unit` через конфиг Unit.

## [0.0.2] - 2026-06-08

### Добавлено

- В `test/smoke.sh` появился флаг `--build` (вместе с `--php X.Y`): один вызов
  покрывает весь конвейер сборка -> запуск -> проверка. Версия PHP берётся из
  `--php`, иначе из тега `phpX.Y` в ссылке на образ, иначе из дефолта ARG в
  `Dockerfile`. Без `--build` скрипт по-прежнему тестирует готовый образ, поэтому
  `make test` и шаг build+smoke в CI не меняются.

### Исправлено

- `rootfs/docker-entrypoint.sh`: остановка демона после первичной настройки
  оформлена явным `if` вместо однострочника `[ -f pid ] && kill … || true` — это
  устраняет падение ShellCheck SC2015 на версии shellcheck с CI-раннера и яснее
  выражает намерение.
- `test/smoke.sh`: проверка загруженного сертификата теперь опрашивает
  управляющий сокет Unit с повторами — это устраняет плавающее падение CI, когда
  контроллер не успевал перезапуститься после первичной настройки до
  единственной пробы.

## [0.0.1] - 2026-06-08

Первый публичный релиз. Поставляет FreeUnit `1.35.5-build4` с PHP 8.3, 8.4 или
8.5 на Debian trixie (amd64).

### Добавлено

- Единый параметризованный многоэтапный `Dockerfile` (`base_image` →
  `php_image` → `final_image`), покрывающий всю матрицу версия-PHP / suite /
  релиз-FreeUnit через build-args — без кодогенерации и каталогов под каждый
  вариант.
- Поддержка PHP **8.3 / 8.4 / 8.5**, по одному встроенному PHP на образ,
  установка из репозитория [deb.sury.org](https://deb.sury.org) со стандартным
  набором расширений; хрупкие расширения (`imagick`, `uploadprogress`)
  ставятся по принципу best-effort, поэтому новая ветка PHP без них всё равно
  собирается.
- Ядро демона FreeUnit и модуль PHP устанавливаются из готовых `.deb`-пакетов,
  скачиваемых из [GitHub-релиза](https://github.com/6RUN0/freeunit/releases), а
  не компилируются из исходников.
- Целостность цепочки поставки при загрузке `.deb`: каждый пакет сверяется с
  `SHA256SUMS` релиза, проверяется наличие обеих ожидаемых записей (чтобы
  `--ignore-missing` не прошёл вхолостую), а сам `SHA256SUMS` зафиксирован в
  системе контроля версий по своему SHA256, что разрывает самоссылочную
  загрузку.
- Загрузки, закреплённые на HTTPS (`--proto-redir '=https'`), для ключа подписи
  sury и ассетов релиза — так редирект не сможет понизить якорь доверия до
  открытого текста.
- deb.sury.org подключён как источник deb822 со своим ключом подписи и apt-пином
  (приоритет 990: предпочтителен для равных-или-новее версий, но не может
  принудительно понизить пакет Debian).
- Оверлей `rootfs/` с entrypoint, который при первом запуске применяет всё
  содержимое `/docker-entrypoint.d/`: `*.sh` исполняются, `*.pem` загружаются как
  набор сертификатов, `*.json` отправляются `PUT`-запросом в конфиг Unit через
  управляющий сокет.
- Runtime-API через переменные окружения (`APPLICATION_USER` / `_UID` /
  `_GROUP` / `_GID` / `_DIR` / `_CHOWN`, `UNIT_ENTRYPOINT_QUIET_LOGS`) для
  пользователя/группы приложения и владельца его каталога.
- `HEALTHCHECK`, опрашивающий управляющий сокет Unit, поэтому проверка живучести
  работает без фиксированного порта приложения и под `--cap-drop=ALL`.
- `Makefile`, управляющий матричной сборкой, с целями `all` / `php<X.Y>` /
  `latest` / `test` / `lint` / `scan`; значения по умолчанию для релиза берутся
  из единственного источника — ARG-ов `Dockerfile`.
- Сквозной smoke-тест (`test/smoke.sh`), который запускает образ и проверяет, что
  entrypoint обработал `*.json`, `*.sh` и `*.pem`, с одноразовым сертификатом,
  сгенерированным в рантайме (приватный ключ не коммитится).
- CI-воркфлоу (`.github/workflows/ci.yml`): линт (hadolint / shellcheck /
  typos), матрица сборки + smoke (8.3 / 8.4 / 8.5) и trivy-скан в режиме отчёта.
- Релизный воркфлоу по тегу (`.github/workflows/release.yml`): на тег `v*`
  собирает и smoke-тестирует матрицу, публикует образы в GHCR и создаёт
  GitHub Release с заметками из соответствующего раздела `CHANGELOG.md`.
- Документация: `README.md` / `README.ru.md` (runtime-API, модель безопасности,
  разделение апстрим/форк) и `CLAUDE.md` с указаниями по репозиторию.
