# Список изменений

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

Версии здесь относятся к **упаковке** (этому репозиторию), а не к встроенному
ПО; каждый релиз фиксирует версии FreeUnit и PHP, которые он поставляет.

## [Не выпущено]

### Изменено

- **Ребрендинг FreeUnit (ломающее изменение для дочерних образов).** Апстрим
  переименовал Debian-пакеты и идентичность на диске с `unit*` на `freeunit*`, и
  образ следует за ним: демон — `freeunitd`/`freeunitd-debug`, каталог состояния —
  `/var/lib/freeunit`, управляющий сокет — `/var/run/control.freeunit.sock`, лог —
  `/var/log/freeunit.log`, пользователь/группа приложения по умолчанию — `freeunit`
  (было `unit`). Дочерние образы должны заменить ключи `user`/`group` в
  `config.json` и любую кастомную команду запуска с `unit`/`unitd` на
  `freeunit`/`freeunitd`; библиотека entrypoint сохраняет имена функций и
  идентификаторы переменных `UNIT_*`/`APPLICATION_*`, поэтому хуки, использующие
  только документированный API, не затронуты.
- Версия встроенного релиза FreeUnit `.deb` поднята до `1.35.6-build2` (`1.35.6-1`),
  пересчитан якорь доверия `FREEUNIT_SHA256SUMS_SHA256`.
- Идентичность бренда вынесена в единый источник — `ARG` в `Dockerfile`,
  повторяющие словарь апстрим-упаковки (`BRAND`, `RUNTIME`, `RUNDIR`, `BRAND_TITLE`,
  `HOMEPAGE`, `DOCS_URL`). По умолчанию `freeunit`/`/var/run`, и сборка теперь
  **проверяет, что вкомпилированные пути установленного бинаря совпадают с
  `RUNTIME`/`RUNDIR`**, поэтому смена идентичности в апстриме уронит сборку, а не
  выпустит образ, чей entrypoint управляет не теми путями.
- Команда запуска по умолчанию перенесена из `CMD` в `Dockerfile` в entrypoint, а
  `HEALTHCHECK` стал скриптом (`/docker-healthcheck.sh`), чтобы имя бинаря и путь
  управляющего сокета оставались в едином источнике (`docker-entrypoint-common.sh`),
  а не дублировались в инструкции exec-формы, которая не раскрывает build ARG.

## [0.0.5] - 2026-06-09

### Добавлено

- `examples/` выросли в набор с покрытием возможностей: `dev` (цикл разработки с
  живым монтированием, пишущий в постоянный том состояния от непривилегированного
  пользователя приложения), `routing` (несколько приложений за путевыми маршрутами,
  отдача статики и индивидуальный `memory_limit` PHP на приложение) и `web-app`
  (HTTPS из самоподписанного сертификата, генерируемого в entrypoint, с
  перенаправлением HTTP в HTTPS) — вдобавок к уже имевшимся `basic` и `cron-hook`.
  Каждый пример — самодостаточный подкаталог со своим README.
- `make test-examples`: гейт примеров, который статически линтит compose-файл
  каждого примера на блок усиления привилегий (`cap_drop`, `no-new-privileges`,
  `SETUID`, `SETGID`), а затем собирает, запускает и проверяет каждый пример
  целиком против только что собранного образа.
- `make help`: самодокументируемый список целей, разбираемый из комментариев-
  аннотаций с префиксом `##` на самих целях.

### Изменено

- Пример `cron-hook` выполняет задачу ежесекундно, используя семиполевой (с
  секундами) синтаксис crontab supercronic, поэтому пример и его тест больше не
  ждут целую минуту до срабатывания.
- CI проверяет, что матрица сборки PHP синхронна между `ci.yml`, `release.yml`,
  `security-scan.yml` и гейтом полноты в `check-upstream.yml` относительно
  `PHP_VERSIONS` из Makefile, и валит job линтинга при любом расхождении.
- `release.yml` защищает каждое извлечение ARG из Dockerfile, громко падая вместо
  публикации некорректного тега, если формат строки ARG когда-нибудь изменится.
- Гигиена репозитория: добавлен `.gitattributes`, ужесточён `.editorconfig` и
  игнорируются рабочие заметки `docs/superpowers/`.

### Исправлено

- Документация: исправлен приоритет пина deb.sury.org в `CLAUDE.md` (990, а не
  1001 — ниже 1000, чтобы скомпрометированное зеркало не могло форсировать
  downgrade) и устаревшие комментарии о числе полей crontab в тесте примеров;
  документация приведена в соответствие с отгруженными `Dockerfile` и crontab.

## [0.0.4] - 2026-06-09

### Добавлено

- Расширяемая система хуков entrypoint: дочерний образ добавляет режим запуска,
  положив хук `handle_<команда>` в `/docker-entrypoint-hook.d/` (он подключается и
  проверяется на владельца под root до сброса привилегий), а сам entrypoint стал
  тонким диспетчером поверх переиспользуемой core-библиотеки
  (`docker-entrypoint-common.sh`): логирование, жизненный цикл демона,
  применители конфигов, сброс привилегий и провижининг пользователя. Дочерние
  образы наследуют каждый фикс надёжности/безопасности базы, не переопределяя
  `/docker-entrypoint.sh`.
- `examples/cron-hook/`: пример системы хуков — один образ работает в двух ролях,
  веб-сервер Unit и долгоживущий cron-раннер `supercronic`, выбираемых для каждого
  контейнера командой (`supercronic` запинен и проверяется по SHA256).
- В `test/entrypoint-lib.sh` добавлены проверки контракта диспетчинга хуков
  (`dispatch_handler`), сброса привилегий `exec_as_user`, валидации и
  идемпотентности `setup_user`, границы пусто/непусто у `dir_has_content`, а также
  pidfile без завершающего перевода строки и с нечисловым содержимым. Общий для
  обоих тест-скриптов разбор CLI и сборка образа вынесены в `test/lib.sh`.

### Изменено

- `apply_config` теперь предупреждает, когда в `/docker-entrypoint.d` больше
  одного `*.json`: `PUT /config` заменяет всю конфигурацию, поэтому в силу
  вступает только лексически последний файл.
- `wait_for_control_socket` ограничивает каждую пробу через `curl --max-time`, а
  `run_entrypoint_scripts` теперь сообщает, какой пользовательский скрипт упал.
- `examples/` реорганизованы так, что каждый пример — самодостаточный подкаталог
  (`examples/basic/`, `examples/cron-hook/`) с индексным `README.md`.
- CI пинит ShellCheck к версии, используемой локально (бандловый на раннере давал
  ложные срабатывания на функциях библиотеки с опциональными аргументами и
  вызываемых через trap/диспетчер), и теперь линтит `README.md` каждого примера.

### Исправлено

- Хук `handle_<cmd>` дочернего образа, завершившийся с ненулевым кодом, больше не
  обрывает entrypoint молча под `set -e` до диагностики. Диспетчинг вынесен в
  `dispatch_handler`, который сообщает понятным сообщением и о ненулевом выходе, и
  о возврате без `exec`.
- `stop_unit` больше не пропускает `kill -TERM`, когда в pidfile нет завершающего
  перевода строки (`read` возвращает ненулевой код на EOF даже после присваивания
  значения). Новый помощник `read_pid` отвязывает значение от кода возврата `read`
  и игнорирует нечисловой pid, поэтому повреждённый pidfile не приведёт к широкому
  kill.
- `dir_has_content` трактует существующий, но нечитаемый каталог как ошибку, а не
  как «пусто», поэтому временный `EACCES` на каталоге состояния не запустит
  повторную инициализацию поверх заполненного состояния.

### Безопасность

- `exec_as_user` теперь передаёт `setpriv --no-new-privs`, поэтому сброс привилегий
  в хуке дочернего образа необратим внутри образа, даже если оператор не указал
  `--security-opt=no-new-privileges`.
- Очистка состояния при провале первого запуска (`find … -delete`) получила
  `-xdev`, поэтому она останавливается на границах файловых систем и никогда не
  удаляет сквозь host-том, вмонтированный внутрь `/var/lib/unit`.
- `apply_certificates` валидирует имя набора по `[A-Za-z0-9._-]`, поэтому
  подделанное имя файла `*.pem` не сможет перенаправить `PUT` управляющего API на
  другой эндпоинт.

## [0.0.3] - 2026-06-08

### Добавлено

- Аттестации цепочки поставки при релизе: `release.yml` теперь генерирует
  SPDX-SBOM для каждого публикуемого образа и записывает безключевые (OIDC)
  аттестации происхождения сборки и SBOM, которые публикуются в GHCR как
  OCI-referrer'ы манифеста образа. Проверить скачанный образ:
  `gh attestation verify oci://ghcr.io/6run0/freeunit-php@<digest> --owner 6RUN0`.
- `.github/workflows/check-upstream.yml`: еженедельная (и запускаемая вручную)
  задача, которая следит за репозиторием пакетов FreeUnit и при новом релизе
  открывает PR с бампом — она пересчитывает закреплённый якорь доверия
  `FREEUNIT_SHA256SUMS_SHA256` и отказывается обновляться, если в новом
  `SHA256SUMS` нет модульного `.deb` для каждой ветки PHP из матрицы.
- `.github/dependabot.yml`: еженедельные сгруппированные PR с бампами для
  GitHub Actions, закреплённых по SHA.
- В lint-задачу CI добавлены проверки воркфлоу и markdown: actionlint, zizmor
  (аудит безопасности воркфлоу) и rumdl.
- Trivy-скан в CI теперь выдаёт SARIF и загружает его в GitHub code scanning,
  поэтому CVE отображаются во вкладке Security и отслеживаются во времени.
- `.github/workflows/security-scan.yml`: еженедельный (и запускаемый вручную)
  повторный trivy-скан *опубликованных* образов в GHCR по каждой ветке PHP,
  чтобы уязвимости, раскрытые после релиза, всплывали без нового push.
- `examples/`: самодостаточный, ужесточённый по безопасности деплой — маленький
  `Dockerfile` запекает приложение и его конфиг Unit в опубликованный базовый
  образ (конфиг копируется в `/docker-entrypoint.d`, без bind-mount'ов),
  запускается с cap-drop + `no-new-privileges` и воркером со сбросом до
  пользователя `unit`.

### Изменено

- Матрица сборки+smoke в CI теперь идёт через Buildx с послойным кэшем GitHub
  Actions на каждую версию PHP (`type=gha`), поэтому повторные прогоны
  переиспользуют слои apt/загрузок вместо сборки с нуля; trivy-скан переиспользует
  образ 8.4, а не собирает свой.
- Smoke-тест теперь запускает контейнер под задокументированным hardening
  (`--cap-drop=ALL …`), поэтому регрессия, ломающая запуск с cap-drop (например,
  не-root-owned каталог состояния), ловится в CI; уже проверяемая загрузка
  `*.pem` задействует затронутое хранилище сертификатов.

### Исправлено

- Контейнер не стартовал под описанным в README hardening (`--cap-drop=ALL …`):
  каталог `/var/lib/unit` принадлежал `unit:unit`, поэтому root-мастер `unitd` —
  лишённый `CAP_DAC_OVERRIDE` из-за сброшенных capabilities — не мог создать свои
  хранилища `certs/` и `scripts/` (`mkdir … EACCES`) и падал на сохранении
  конфигурации. Теперь каталог состояния остаётся во владении root (мастер по
  замыслу работает от root), поэтому запуск с cap-drop работает; воркер
  приложения по-прежнему сбрасывается до `unit` через конфиг Unit.

## [0.0.2] - 2026-06-08

### Добавлено

- В `test/smoke.sh` появился флаг `--build` (вместе с `--php X.Y`): один вызов
  покрывает весь конвейер сборка -> запуск -> проверка. Версия PHP берётся из
  `--php`, иначе из тега `phpX.Y` в ссылке на образ, иначе из дефолта ARG в
  `Dockerfile`. Без `--build` скрипт по-прежнему тестирует готовый образ, поэтому
  `make test` и шаг build+smoke в CI не меняются.

### Исправлено

- `rootfs/docker-entrypoint.sh`: остановка демона после первичной настройки
  оформлена явным `if` вместо однострочника `[ -f pid ] && kill … || true` — это
  устраняет падение ShellCheck SC2015 на версии shellcheck с CI-раннера и яснее
  выражает намерение.
- `test/smoke.sh`: проверка загруженного сертификата теперь опрашивает
  управляющий сокет Unit с повторами — это устраняет плавающее падение CI, когда
  контроллер не успевал перезапуститься после первичной настройки до
  единственной пробы.

## [0.0.1] - 2026-06-08

Первый публичный релиз. Поставляет FreeUnit `1.35.5-build4` с PHP 8.3, 8.4 или
8.5 на Debian trixie (amd64).

### Добавлено

- Единый параметризованный многоэтапный `Dockerfile` (`base_image` →
  `php_image` → `final_image`), покрывающий всю матрицу версия-PHP / suite /
  релиз-FreeUnit через build-args — без кодогенерации и каталогов под каждый
  вариант.
- Поддержка PHP **8.3 / 8.4 / 8.5**, по одному встроенному PHP на образ,
  установка из репозитория [deb.sury.org](https://deb.sury.org) со стандартным
  набором расширений; хрупкие расширения (`imagick`, `uploadprogress`)
  ставятся по принципу best-effort, поэтому новая ветка PHP без них всё равно
  собирается.
- Ядро демона FreeUnit и модуль PHP устанавливаются из готовых `.deb`-пакетов,
  скачиваемых из [GitHub-релиза](https://github.com/6RUN0/freeunit/releases), а
  не компилируются из исходников.
- Целостность цепочки поставки при загрузке `.deb`: каждый пакет сверяется с
  `SHA256SUMS` релиза, проверяется наличие обеих ожидаемых записей (чтобы
  `--ignore-missing` не прошёл вхолостую), а сам `SHA256SUMS` зафиксирован в
  системе контроля версий по своему SHA256, что разрывает самоссылочную
  загрузку.
- Загрузки, закреплённые на HTTPS (`--proto-redir '=https'`), для ключа подписи
  sury и ассетов релиза — так редирект не сможет понизить якорь доверия до
  открытого текста.
- deb.sury.org подключён как источник deb822 со своим ключом подписи и apt-пином
  (приоритет 990: предпочтителен для равных-или-новее версий, но не может
  принудительно понизить пакет Debian).
- Оверлей `rootfs/` с entrypoint, который при первом запуске применяет всё
  содержимое `/docker-entrypoint.d/`: `*.sh` исполняются, `*.pem` загружаются как
  набор сертификатов, `*.json` отправляются `PUT`-запросом в конфиг Unit через
  управляющий сокет.
- Runtime-API через переменные окружения (`APPLICATION_USER` / `_UID` /
  `_GROUP` / `_GID` / `_DIR` / `_CHOWN`, `UNIT_ENTRYPOINT_QUIET_LOGS`) для
  пользователя/группы приложения и владельца его каталога.
- `HEALTHCHECK`, опрашивающий управляющий сокет Unit, поэтому проверка живучести
  работает без фиксированного порта приложения и под `--cap-drop=ALL`.
- `Makefile`, управляющий матричной сборкой, с целями `all` / `php<X.Y>` /
  `latest` / `test` / `lint` / `scan`; значения по умолчанию для релиза берутся
  из единственного источника — ARG-ов `Dockerfile`.
- Сквозной smoke-тест (`test/smoke.sh`), который запускает образ и проверяет, что
  entrypoint обработал `*.json`, `*.sh` и `*.pem`, с одноразовым сертификатом,
  сгенерированным в рантайме (приватный ключ не коммитится).
- CI-воркфлоу (`.github/workflows/ci.yml`): линт (hadolint / shellcheck /
  typos), матрица сборки + smoke (8.3 / 8.4 / 8.5) и trivy-скан в режиме отчёта.
- Релизный воркфлоу по тегу (`.github/workflows/release.yml`): на тег `v*`
  собирает и smoke-тестирует матрицу, публикует образы в GHCR и создаёт
  GitHub Release с заметками из соответствующего раздела `CHANGELOG.md`.
- Документация: `README.md` / `README.ru.md` (runtime-API, модель безопасности,
  разделение апстрим/форк) и `CLAUDE.md` с указаниями по репозиторию.
